# Spec, State and hierarchy

Read for durable checkpoints/resume State or when discovery may change a binding contract.

## Resolve uncertainty

Repository fact → inspect evidence. Inaccessible evidence → report its limit. Reversible wiring → bounded hypothesis. Material product/scope/permission/acceptance choice → ask the Owner before binding it. Optional authorized advice has a specific evidence-backed question and cannot replace that decision.

Spec binds observable outcome/acceptance, scope/non-goals, Owner decisions, semantic ownership, allowed writer domains, authority, hard dependencies and required evidence/stop/recovery boundaries. Bind an exact mechanism only when alternatives would violate one of these; name the failure it prevents.

Hypotheses may include likely files, helpers, call paths and internal sequencing. Name what can vary and which Spec/guardrails must hold. Do not use a hypothesis to smuggle in another writer domain or permission.

State is the minimal truthful resume projection, shaped only by repo-docs-system's progress template. Update it for execution truth/deviations; no copy of the Spec or review transcript.

## Choose depth

Steps are local actions. A checkpoint produces an independently meaningful outcome for review/resume. Several checkpoints need no Stage unless their composition creates an intermediate accepted/published/rollback gate for downstream work. Reading/editing/formatting alone is not a checkpoint.

A final cumulative review is needed when correctness depends on composition that checkpoint evidence cannot prove; no extra review layer for file count alone.

## Discovery route

- Equivalent wiring preserves Spec/guardrails: verify, record a bounded deviation in State and continue within authority.
- Completion or resume position changes: update State.
- New semantic owner, writer domain, authority, hard dependency, evidence or rollback boundary: stop affected work and correct/review its contract.
- Product meaning, acceptance or scope changes: Owner decision before amending Spec.
- Insufficient evidence to classify safely: preserve the unresolved/blocked state, do not guess.

A program plan links to progress; a standalone durable plan without program progress may use the existing inline-State exception. Do not create a separate tracker, Stage file or owner brief without a real consumer.
