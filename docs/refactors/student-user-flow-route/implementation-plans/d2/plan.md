## 1. Objective, scope, authority

Deliver teacher-managed public Preview for a bounded set of course topics. A guest, unenrolled account, or enrolled learner deliberately entering Preview can read the full eligible topic, practise its cards and exercises, and get immediate correctness without creating or mutating persistent course-learning state. Correct chapter creation/management authority and legacy creator identity are necessary D2 foundations. Preserve D1 topic authorship/review and Q7 internal read, enrolled-write, and private-media boundaries.

In scope: chapter creator migration and authority, preview marker/quota and lifecycle composition, teacher controls and destructive dialogs, public syllabus/Preview read and stateless answer/media paths, fixtures, integration/browser verification, and current status documentation. Excluded: D3 memory stage, D4 completion redesign, broad `LEARNING-INTEGRITY-001` relation repair, payment, collaborator redesign, candidate revisions, and historical D1/Q7 document rewrites. Work remains on one feature branch; each implementation checkpoint below requires its own evidence and review before a local commit is proposed. This plan/design work grants no implementation or remote action.

The newer Owner instruction supersedes the master plan's older owner/co-owner-only marker wording: **editor may manage Preview markers**. It also clarifies effective activity through the parent chapter and requires automatic removal of markers inside a deleted chapter. The master plan still owns the 20% cap, draft denominator, publication gates, full read-only content/media, transient correctness, and D1 → Q7 → D2 order. The master plan and `problems.md` retain historical row-local `removed_at` wording; D2 uses the repository-confirmed effective chapter lifecycle below. Reconcile current program owners when D2 ships, without rewriting historical reviews.

## 3. Target authority and chapter contract

| --- | --- | --- | --- | --- | --- |
| Current owner/co-owner | Yes | Any in course | Any in course | Yes, course-wide | Yes, eligible course topics |
| Current editor | Yes | Own recorded chapter only | Own recorded chapter only | **No** | Yes, eligible course topics |
| Previewer | No | No | No | No | No |
| Non-member/learner | No | No | No | No | No |
| Global admin without course membership | No ordinary authoring authority; moderation uses its separate audited path | No | No | No | No |

DB/RPC/RLS must enforce this matrix even on direct Data API writes. An active local course collaborator with profile role `student` or `admin` follows their **course** role in this matrix, consistent with D1; the global admin role alone grants no normal chapter/marker authority. Refine course-wide chapter authoring checks to enforce creator-scoped editor update/hide/restore and owner/co-owner-only reorder; inspect chapter INSERT/UPDATE and deleted-row SELECT policies plus create/reorder RPCs. Validate old and new row, immutable creator, course identity, and allowed changed columns rather than relying on hidden controls. Editor rename/update follows the same creator scope, and editor deleted-row SELECT is limited to own restorable chapters. Existing D1 topic capability stays independent: chapter ownership does not grant topic authorship, review, or topic reorder. A role downgrade preserves creator identity but removes editor mutation authority; removal likewise does not transfer historical identity.

Normal chapter hide soft-deletes only its row and preserves descendants; additionally D2 clears all Preview markers on its child topics atomically. **An active pending child freezes ordinary chapter mutation before D2 quota resolution; ordinary hide/delete never cancels its review to get past D1.** Normal restore needs an explicit authorized path (currently absent), requires active course and current chapter authority, and appends the chapter at a conflict-free end position without rewriting its title. Recompute quota before commit. UI numbering is **position among active chapters sorted by canonical `order_index`** (then existing stable tie-break), starting at 1; never store a generated “Chapter N” prefix in `title`. Existing title text is not mass-renamed.

## 4. Preview eligibility, quota, and mutation contract

Define `A` as topics with nonremoved row and matching nonremoved parent chapter in this course, including draft/pending. Define `M` as marked topics in `A`, regardless of publication. From a valid allocation, every ordinary quota-affecting commit must leave `M <= ceil(A / 5)`; when `A=0`, cap is zero. A topic under a removed chapter is effectively inactive, even if its own `removed_at` remains null. `topics.is_preview` defaults false, is non-null, and is absent from ordinary authenticated topic UPDATE grants.

Only privileged audited moderation may **create** a committed `M > cap` episode (§7). While that episode exists, otherwise valid ordinary topic creation or topic/chapter restore may increase `A` with no marker increase and may commit through intermediate still-over-cap counts; they must not increase the excess or bypass D1 authority. Recompute the allocation after each such transaction and clear the causal pointer in the transaction that first reaches `M <= cap`. Apart from this non-worsening growth, ordinary quota-affecting operations must finish within cap, including batch marker recovery. Public Preview fails closed for any observed over-cap allocation, including integrity drift; the causal audit binding determines whether the teacher may be shown a specific moderation reason.

| Course | Chapter | Topic | Marker | Public syllabus / full Preview |
| --- | --- | --- | --- | --- |
| Active published, `M <= cap` | Active | Active published | On | Link / full guarded read, correctness, media |
| Active published, `M > cap` | Active | Active published | On | Generic Preview-unavailable state; all content, correctness, and private media denied |
| Active published | Active | Active published | Off | Locked row / denied |
| Active published | Active | Active draft or pending | Either | No public topic / denied |
| Draft or removed | Any | Any | Either | No public course / denied |
| Active published | Removed | Any | Either | No topic / denied |
| Active published | Active | Removed | Either | No topic / denied |

Marker mutation is available to current owner/co-owner/editor, including a marker on draft/pending topic without publishing it. Previewer and unrelated actor denied. The read, answer, and media boundaries recheck course, chapter, topic, status, marker, parent chain, and **current `M <= cap`** on each fresh request. Enrollment never changes Preview behavior; `/learn` remains persistent learning mode.

Use one course-serialized transactional boundary for marker changes and lifecycle operations that change `A` or `M`, including topic creation/restore and chapter restore. Reuse the established course lock order and validate IDs/course membership under the lock. Direct Data API update/restore paths must not bypass the normal-authoring guard or causal-pointer cleanup; the guard must recognize the narrow audited moderation path and permitted non-worsening denominator growth during an existing episode. Avoid a trigger/RPC combination whose intermediate statement fails before an otherwise valid atomic operation; unmark first when required, then mutate, and validate projected final state in the same transaction. No partial success. For stale selection/capability/status or concurrent mutation, reject safely and return a fresh allocation snapshot for the UI. Marker-based recovery selects enough currently active markers and unmarks them **together**, ending at `M <= cap`; ordinary one-at-a-time unmark commits that remain over cap are invalid. Denominator growth may reach validity across multiple authorized transactions without selecting unrelated markers.

**Normal chapter hide:** reject with D1's `TOPIC_PENDING_FROZEN` if an active pending child exists; no review cancellation occurs. Only for an otherwise valid hide, clear *every* marker on topics inside the target chapter, including individually removed child rows, regardless of quota. Compute projected `A`, `M`, and cap excluding the chapter and those markers. If remaining marked topics outside it exceed cap, show the exact additional count and let an authorized actor select those outside markers. Atomically unmark the selected outside topics, clear internal markers, and hide the chapter. Cancellation leaves all rows unchanged. An editor may select outside markers because marker authority is course-wide, but may hide only their own chapter. Never silently unmark outside topics.

Topic delete/restore and chapter restore must compose with the D1 lifecycle and quota. **Ordinary topic soft-delete atomically clears that topic's Preview marker**, including when the deleter has D1 delete capability but no course-wide marker-management authority; this target cleanup does not grant authority to select unrelated markers. A restored topic stays unmarked and `draft`: restore must not revive its old Preview marker, and only a later explicit owner/co-owner/editor action may mark it again under the then-current quota. When denominator reduction would overrun cap after target cleanup, actors with marker authority resolve inline by explicitly selecting additional active marked topics; a D1 topic deleter without marker authority gets a blocked state and a course manager handoff, never borrowed authority. Preserve D1 published-delete confirmation, pending cancellation, and restore-to-draft semantics. The Builder and Structure entry points must reach the same server result. Do not silently cascade-delete topic content.

## 5. Public, learning-state, and Q7 media boundaries

Replace the temporary first-topic flag in `app/actions/public-course.ts` and its DTO with persisted eligibility in the public read model. Strict server DTO validation and request-time no-store/revalidation avoid serving revoked content from a stale page. The Preview controller reuses presentation components only where callbacks are stateless. Again/Hard may requeue a card locally; Good/Easy may remove it locally; refresh may reset the session. Verify zero persistent course-learning delta for an **already enrolled** actor as well as guests and unenrolled accounts.

Keep Q7's buckets private, Storage policies and authenticated media route intact. A dedicated public media endpoint accepts persisted group ID/type, resolves the guarded parent chain and stored canonical/known-legacy reference on the server, verifies course/topic/object identity and current quota, and downloads only that object with a server-only privileged client. No arbitrary browser bucket/path, anonymous broad Storage SELECT, or service credential in DTO. Preserve MIME, audio Range, `nosniff`, and `no-store`. External URLs retain Q7's external-host limitation. Inspect card media separately and provide the same eligibility-safe delivery if managed private card media exists; production Q7 pre-deploy inventory showed no persisted card media, which is not a future guarantee. Cached/downloaded bytes cannot be revoked retroactively.

## 7. Moderation exception, causal warning, risks, and handoff

**Owner decision.** Global platform-admin moderation must proceed when otherwise valid even if Preview quota would be exceeded. This is separate from ordinary chapter authoring. In `20260915100000_d1_trusted_lifecycle.sql`, `can_modify_chapter_by_id` and `d1_guard_chapter_mutation` freeze an ordinary chapter mutation with an active pending child. In `20260915130000_d1_correction_security_rescue.sql`, `moderate_platform_content` instead locks the course/children, calls `d1_cancel_pending_reviews_for_topics` (cancels submissions and moves pending topics to `draft`), then soft-deletes the chapter and inserts an audit row in the same transaction. Course demote/takedown and pending topic moderation also call the trusted cancellation helper when applicable. **Preserve the chapter moderation sequence**; D2 quota cannot block it, and the moderator receives no normal marker-selection or chapter-authoring authority. A failed moderation transaction rolls all those effects back together.

Clear markers owned by the moderated target in that transaction: topic takedown clears its marker; chapter takedown clears all child markers, including individually removed children; course takedown clears all markers in the course. Do not unmark unaffected active topics. Topic `demote`/`invalidate_review` and course `demote` make public content ineligible as appropriate and normally leave active-topic `A/M` unchanged, so retain their markers. **Recompute final `A/M` for every moderation action**: the current topic moderation SQL also sets `removed_at = NULL` on demote/invalidate, so an otherwise valid unusual removed-state target could change effective activity. A valid topic/chapter takedown may reduce `A` enough that surviving `M > cap` commits. Any otherwise valid audited moderation action may create the **only permitted over-cap episode**; subsequent authorized denominator growth may carry the same episode without worsening it until valid again. Do not install an unconditional constraint that rejects moderation or that permitted growth.

Derive suspension from canonical effective `M > cap` at the guarded public read/answer/media boundaries; do not add a duplicate course status enum. All Preview access fails closed until allocation is valid. Public course detail, enrollment/payment and enrolled `Tiếp tục học` remain normal where the course itself is eligible; public copy reveals no moderation or quota detail. If unexpected integrity drift also yields `M > cap`, fail closed without falsely claiming moderation causality.

The teacher warning needs a **deterministic causal audit ID**. `platform_moderation_audits` has `id`, `target_type`, `target_id`, `action`, `reason`, previous-state fields and `created_at`, with no normal authenticated SELECT grant; the current moderation RPC inserts the audit but returns only JSONB without its ID. Add a narrow private per-course active-cause pointer (`course_id` → `audit_id`, constrained to the existing audit row) rather than an event log or duplicated reason/status. Extend the same audited RPC to capture `INSERT ... RETURNING id` and, under its course lock, set the pointer only when an otherwise valid moderation action changes a valid allocation into over-cap. Retain the **first causal audit** while later actions leave that episode over-cap. Under the same course lock, clear the pointer on **every** transition back to `M <= cap`, including valid topic creation/restore or chapter restore that grows `A` while `M` stays fixed, not just explicit marker unmark; course takedown also clears it. Intermediate growth keeps the pointer while over-cap. A later new episode gets a new pointer. A targeted server/RPC read validates that the referenced audit action and target belong to the same course, then exposes current `M/cap`, exact excess, target summary and that audit's `reason` only to current course owner/co-owner/editor; previewer and public readers cannot query the pointer/audit. Soft-deleted topic/chapter rows retain their `course_id`, but if a target label is no longer resolvable, show its type instead of guessing. A missing/mismatched pointer while over-cap is an integrity stop/repair condition for the specific explanation, not permission to choose the latest audit or reopen public Preview.

On Overview/Structure, show a compact recovery warning with `M/cap`, excess, causal target/reason when bound, and `Điều chỉnh bài học xem thử`. Reuse the marker allocation control: owner/co_owner/editor may select enough active marked topics to unmark **atomically** to `M <= cap`. Valid topic creation/restore may instead grow the denominator until the cap reaches `M`, with no marker changes. Either route clears the pointer on the first valid allocation and restores Preview eligibility automatically. Previewer cannot resolve or view the reason. No separate reactivation button, general changelog, inbox, or admin identity is required.

Additional risks: existing course-wide chapter checks let an editor mutate/reorder chapters outside D2's creator/no-reorder scope and must be narrowed without disabling owner/co-owner authoring or separate audited moderation; RLS `UPDATE` also needs row SELECT; `SECURITY DEFINER` grants/`search_path` and pointer privileges must be checked; direct Data API and legacy RPCs can bypass an Action-only cap or target-marker cleanup; private media may have canonical/legacy/external references; downloaded bytes remain with the recipient. A fresh production creator-candidate and media inventory is a rollout prerequisite. Stop if deployment data differ, if D1/Q7 access gates must be weakened, if the exact causal audit cannot be bound atomically, or if no lock/guard design can allow valid moderation while rejecting ordinary over-cap commits.
