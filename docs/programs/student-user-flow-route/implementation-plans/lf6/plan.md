## 1. Binding Spec

### 1.1 Outcome and acceptance

Outcome: after this unit merges, the learner can jump between the topic's unlocked stages from the stage thread, and the completion screen points to it with one `Xem lại` button. A tap on a locked stage says why it is locked. The FSRS review sheet uses the same rating colours as the workspace, and both flip a card more slowly. Finishing a due-card or full review queue shows a review toast and returns the learner to where the review belongs instead of the first-learning toast and stage jump. The header account dropdown shows every destination under reduced motion. The program docs record the LF5 merge, close FEAT-005 and FUTURE-REVIEW-001, and move the solved PR7 ordering entries out of the teacher program's open list.

## 3. Bounded implementation hypotheses

- Thread: render a `button` inside each non-current `li`, keep `aria-current` on the current `li`, add a `reason` state in the workspace that the thread renders under itself in a `role="status"` line; expose the `Xem lại` focus target with a ref or an id on the thread.
- Completion `Xem lại`: the panel receives one `onReview` callback; the workspace scrolls the thread (`scrollIntoView`, `behavior: "auto"` under reduced motion), focuses the first enabled thread button and toggles a short highlight state.
- Ratings: move `RATINGS` classes to a small shared module next to the learning components (for example `_components/rating-styles.ts` or under `lib/`), import it in both; drop `.rating` from the CSS module if it becomes unused.
- HEADER-001: reproduce with Playwright (`emulateMedia({ reducedMotion: "reduce" })`) on the seeded admin, first open and open–close–reopen. Candidates to check, not conclusions: the `forceMount` content and its `data-state`, the items' computed visibility, geometry and animation (fill mode measured from computed style; tw-animate-css defaults to `none`) across open–close–reopen, and Radix collection or roving focus registration with a force-mounted content. Fix in the owning component (`header.tsx` or `dropdown-menu.tsx`) with the smallest change.

## 5. Risks, rollout and rollback

| Risk | Mitigation |
| --- | --- |
| The thread becomes a gate bypass | Locked steps never call the stage functions (G1), and tests cover both locks |
| Buttons break the one-line thread on 320 px | AC3 keeps the layout and the smoke measures it |
| HEADER-001 cannot be reproduced | G3: it stays open, AC7 is unmet, and the Owner decides whether the rest ships |
| A slower flip feels sluggish | 400 ms is the Owner's choice (Q3); reduced motion removes it |

- Rollout: merge after CI, then the production deploy. No migration or hosted step.
- Stop when: a change needs a gate, completion-calculation or server change beyond the AC1 and AC10 behaviour the Owner chose, or the thread cannot stay on one line at 320 px with AC3 hit areas. Report to the Owner.
- Rollback: revert the PR. No data or schema change.
